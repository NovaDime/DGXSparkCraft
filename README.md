# SparkCraft 1.2 · 助力开发你想要的世界

用 NVIDIA DGX Spark 打造游戏 UGC 多智能体“AI 圆桌”协作系统。

**NVIDIA DGX Spark 黑客松 · NVIDIA Developer社区说的都队**

面向 Minecraft 中国版开发。七位圆桌成员分别负责主持、策划、数值、技术可行性、美术、音效与独立审查；程序虾仁负责代码制作。会议形成方案后，由人审核任务单，再自动下发编码和音效任务，检查后生成附加包 ZIP。当前默认目标为中国版基岩 1.24，最终兼容性仍须目标游戏验收。

## DGX Spark 快速开始

Ubuntu / Linux ARM64，Python 3.12+；模型部署需要已配置 NVIDIA 容器运行环境的 Docker。首次需要网络下载 Python 依赖、Node、OpenClaw、模型权重及容器，不是包含模型的离线整机镜像。

```bash
chmod +x *.sh
./一键部署.sh --dry-run   # 查看部署动作，不修改环境
./一键部署.sh            # 准备依赖，复用或部署 Nemotron，启动并打开工作台
```

已有 `.venv`、OpenClaw 和本机模型的用户直接运行：

```bash
./启动.sh               # 启动或复用服务，自动打开默认浏览器 /studio
./后台监控.sh           # 后台健康记录
./结束.sh               # 只结束本项目 Studio、Gateway 与监控
./安装桌面快捷方式.sh    # 为当前位置生成可双击的启动、部署图标
```

Linux 文件管理器可能将 `.sh` 双击解释为打开文本。安装桌面快捷方式后，双击 **SparkCraft 创作工作室**；若桌面提示“允许启动”，按系统提示启用。搬动目录后重新生成快捷方式。无图形界面时启动脚本会打印访问地址。

新版入口：[http://127.0.0.1:8765/studio](http://127.0.0.1:8765/studio)。详细前提、固定版本与下载说明见 [DGX Spark 部署](docs/DGX-Spark部署.md)。部署检测到已有模型/GPU任务时不会将其停止或替换。默认模型端口 8000、项目 Gateway 19789、Studio 8765，均仅本机访问。

## 使用流程

1. **代码库与知识 → 我的世界**：官方 API 与开发指南是默认前置资料，不需要选择代码库才进入 Agent 上下文。卡片区分基础规则、参考快照与官网正文；可刷新资料或上传离线文档。其他游戏显示“未来更新”。
2. 可选上传代码库 ZIP 或导入本机目录，检索引用片段；原目录不被覆盖。文档识别模型支持本地模型与自配云端 API。
3. **开发工作台**：选择“只有想法”或“已有完整策划”，粘贴内容后进入策划圆桌。圆桌中观看讨论，点像素虾查看/更换讨论模型；不满意可提出修改，开启关联原方案的新一轮讨论。讨论最多 1000 轮且受 单次上下文 1M token 上限保护；未解决分歧不会伪装成共识。
4. 形成共识后由策划整合数值、整理程序与素材任务单。由用户审核并批准，进入开发圆桌，自动执行制作、独立审查和打包。StepAudio 默认 `stepaudio-3-gen-preview`，使用自己的 StepFun API Key。
5. 完成时显示下载提示。在工作台或 VS Code 审阅代码、检查证据、下载包。需要目标游戏实测的结果不会标记为已验证。

**调音模型入口**：圆桌下方展开“调音虾尾 · 音频模型 API”，选择 StepFun 服务区域，填写模型 ID 和 API Key。无需先创建会议或制作任务；保存不触发音频生成，密钥仅保存在本机。

**美术模型入口（测试版）**：圆桌下方可填写多模态 API 地址、模型 ID、协议与密钥。这里只保存连接，图像生成适配器尚未启用；不会把本地文本模型当作画图模型。有必需的新美术素材时会阻止批准，可经继续讨论改用已有资源。美术虾绘仍参与美术方案评审，详细 Skill 包含九宫格与序列帧规范。

任务、会议记录可移入回收站并恢复；运行中先停止。会议记录可折叠。经验沉淀采用索引与人工采纳，**不会训练或更改模型权重**。

## 自动启动与 GitHub 下载使用

从 GitHub 下载源码、解压后，在 DGX Spark 上运行 `bash 启动.sh`：若当前没有其他 SparkCraft 实例且尚无 `.venv`，会自动转入首次一键部署。首次需要网络、Python 3.12及venv、Docker、NVIDIA驱动和NVIDIA Container Toolkit；系统组件应由设备管理员事先准备。大模型不随源码分发。

正常启动顺序为检查/准备本机Nemotron → 启动项目OpenClaw Gateway → 启动Studio → 打开浏览器。已有服务直接复用；本部署器带管理标签的停止模型容器会重新启动，正在加载则等待。无匹配服务但GPU或端口占用时明确报错，不强制终止别人的进程。同名但无管理标签的容器也不会被自动接管。

另一目录的SparkCraft已在8765运行时，启动脚本转交给该目录的启动器，检查它的依赖后打开原实例；界面和数据仍属于原目录。想独立运行下载的新副本，应先结束原项目，再从新目录启动。

OpenClaw和模型作为后台服务连接，浏览器打开的是SparkCraft；不需要另外打开模型聊天窗口。StepFun音频需要使用者自己的API密钥，没有密钥仍可使用本地文本协作，但不能真实生成云端音频。便携版不包含作者密钥、模型权重或运行时，不保证未经安装就能在任意电脑运行。


## 首次启动连接检测

`启动.sh` 先检测本地模型列表、OpenClaw 安装状态和专用网关认证，再决定复用、启动或安装。Node/OpenClaw 的已安装版本与项目固定版本一致时直接复用。启动窗口按 5 个阶段显示进度；模型加载显示日志中的真实权重分片百分比，随后单独显示引擎预热阶段，不将容器启动等同于 API 就绪。完整启动在独立后台进程中继续，关闭启动终端不会中断后续 OpenClaw 与 Studio 启动。

启动日志为 `data/runtime/startup.log`，检测结果为 `data/runtime/preflight.json`。工作台每次打开会自动显示“本机连接检测”，可点“重新检测”。8000 是本地模型端口，19789 是本项目独立 OpenClaw；检测到 18789 的通用 OpenClaw 不会擅自改写它的配置。检测不触发模型生成，也不发送云端付费请求。

请完整解压文件夹后运行其中的脚本。单独下载一个 `启动.sh` 无法找到项目代码；Linux 文件管理器若双击只打开文本，请使用终端执行 `bash 启动.sh`，或运行 `bash 安装桌面快捷方式.sh` 后使用桌面图标。

圆桌记录按轮次翻页，待复核问题集中在翻页栏上方。结构输出修复失败会记录未完成评审并继续下一位，不会自动视作认可。1M 限制仅针对单次上下文；本地模型累计 token 用量不限制会议持续轮数。

圆桌采用协作设计：各成员的专业方案会传给后续成员及主持人整合。默认启用可关闭的自动收敛复核，常规轮数结束后必要时追加最多三轮（总计不超过 1000 轮），只有同版方案经成员确认才可提交人工审核。旧会议可点击“继续收敛复核”创建关联讨论。

**Skills 持续学习（测试版）**：上传代码或重新索引后，本地模型自动提炼带逐字源码引用的专业经验，生成版本化 Skill 补充并供圆桌和开发 Agent 使用。代码库详情可查看分析覆盖范围、暂停使用、回滚与下载；基础 Skills 和模型权重保持不变。
