# 验收与交付

读取本 Skill 的 `evals/evals.json` 和 `BENCHMARK.md`。验收场景是供执行者使用的机器可读清单，不是已经跑过的测试，也不是自动调用 SSH 的执行器。

按连接、目标配置校验、Gateway、五个角色真实调用、三/四轮会议、权限与失败行为、资源与专业效果的顺序留证。每条记录写明输入、实际输出、环境与版本、结果、证据路径、日期和执行人。

使用受控的假 Token 检查日志泄露，真实 Token 不作为测试样本。真实用量只取服务报告；没有数值就记 null。耗时包括网关与云端网络，不当作本地模型吞吐率。三轮以前不能收敛，四轮未通过可以是正确的待复核结果。

交付前核对五个角色及本 Skill 的 `SKILL_CARD.json`。填写实际责任人、许可、地域与依赖；保留未确定状态，不能自认代表负责人接受。检查包中卡片和源文件是否一致。

文件清单只证明可比对的内容指纹，不证明来源或签名者。发布负责人提供签名方案和信任根后，对最终包/清单签名，并由接收方验证签名及清单中全部文件的散列。扫描、效果评估、签名、用户接受和重复检查是不同记录，不能互相替代。

当前阶段没有实机性能、工具拒绝、正式签名或比赛认证证据，均保留未完成状态。软件测试通过只能填写本地软件验证栏。完成后把真实材料位置写入记录，不能用本 Skill 的文字当执行证据。
