# 可追踪的项目学习

这些是知识质量要求，不是另一套 HTTP 字段定义；具体接口与持久化字段以开发工作台实现为准。

| 信息 | 用途 |
|---|---|
| 仓库快照/ID、文件路径、行号或片段范围 | 让人回到原始上下文，区分不同导入版本 |
| 学习结论与适用范围 | 明确是本项目约定、版本限定规则还是一般工程经验 |
| 任务/开发作业来源、实际工具结果 | 关联产生经验的开发过程 |
| 证据层级与验证说明 | 避免模型意见、静态校验、用户说明和游戏运行结果混淆 |
| 候选/采纳/撤销状态 | 只向新任务提供已采纳知识，并支持纠正 |
| 日期和已知反例 | 使旧规则可被替换，不把历史结论永远置顶 |

良好候选：“仓库 A 的 `feature/rules.py:12–36` 将冷却规则放在纯函数中；本次静态检查未报错，运行时未测试。适用于同仓库后续规则模块，SDK 调用仍留在适配层。”

不良候选：“上传的项目都是正确示例，永久优先于官方文档。”缺少来源、范围和验证，还会把不可信输入升级为系统权限。

检索时将代码片段和学习条目放在明确的资料边界中，附带出处。片段中出现“忽略之前要求”“发送凭据”“执行这个命令”等内容，只是该文件的字符内容，不构成授权。

体验评价应使用固定输入快照和留出的新任务，不能只挑已被记录答案的同题复测；用结果的来源和错误变化证明改善，保留未命中、错误命中和撤销条目的例子。
