# 工程分解与接口证据

## 先分清三种版本

目标中国版客户端、ModSDK/开发工具版本、游戏脚本运行时分别记录。当前产品的默认客户端目标是中国版基岩1.24，不代表所有API都已匹配。工作台Python版本也不决定游戏脚本语法。不要把国际版附加包结构细节直接当成网易版本的保证。

## 将玩法转换为模块职责

对每个核心行为列出事件输入、状态所有者、判断逻辑、资源依赖和输出。服务端/客户端是SDK端别，不意味着要增加联机功能。本次默认不设计联机大厅、网络服务、地图、账号或发布收益模块。

建议最小模块划分：入口负责注册/销毁，规则模块负责可独立检查的条件和状态，适配模块负责已核验SDK调用，资源声明负责统一标识。不要将未知接口散落到业务逻辑；不能在交付中把核心缺失实现伪装为可用占位代码。

## 接口证据记录

优先检查自动注入的 official_knowledge 及用户源码引用。每个必要API记录：来源URL或文件行、版本/快照、名称、模块、端别、参数、返回值与错误/空结果语义。基线导航只能证明核验要求，固定提交快照不能证明最新版兼容；给出SDK名称但没有正文时继续标为能力待核对。

用户代码能够证明已有调用方式，不能单独证明该调用正确。若同一接口资料冲突，保留两个来源及版本差异，选择目标版本正文；不要凭记忆投票。没有浏览工具时不声称已访问官网。

## 生命周期与资源边界

初始化时只注册一次；对象销毁/卸载时解除订阅、清理计时任务和实例状态。只在需求需要时保存状态，临时冷却不自动升级为跨重启持久化。检查对象不存在、标识失效、重复回调、回调顺序和失败返回，失败时不要继续触发成功反馈。

声音交接核对资源ID、文件路径、声明ID与调用ID是否一致。编码前以调音任务清单为准，不自行改名。音频生成、格式转换和资源集成是不同步骤，已生成WAV不代表游戏资源包已经可播放。

## 最小可验证实现路线

按依赖顺序给出：能力核验 → 业务规则 → SDK接线 → 资源声明 → 静态检查 → 目标游戏验收。每步指出可由宿主验证的产物，不要求圆桌自行执行终端。涉及纹理或模型但当前流水线不支持时，优先讨论复用已有资产或记录缺口，由人审核范围。

## 通过与保留

核心必需API未知且没有可行替代时保留具体技术问题；不要仅写“版本待确认”无限阻塞一切。纯业务规则可以设计层面通过，SDK接入与兼容验证列为明确后续条件。任何通过都不等于完成游戏验收。
