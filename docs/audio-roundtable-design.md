# 调音虾尾与模组音效模块设计

状态：待用户审阅；2026-09-25。本文定义新增功能，尚不表示实现完成。

## 用户目标

SparkCraft 聚焦 Minecraft 中国版模组开发。新增正式圆桌成员“调音虾尾”，负责 NPC 对话语音和物品／交互音效；默认使用 StepFun `stepaudio-3-gen-preview` 生成音频，预留其他模型适配能力。源码将发布到 GitHub，必须排除密钥与本地运行数据。

## 圆桌成员

- 角色 ID：`audio`；名称：调音虾尾；Skill：`minecraft-audio`；使用独立 OpenClaw Agent 与工作区。
- 每轮顺序：策划虾、数值虾、程序虾皮、调音虾尾、程序虾米，随后由主管虾汇总。沿用三至四轮上限。
- 调音虾尾具有与其他评审角色相同的发言、提出分歧、复核自己提出的问题和影响共识的权利。无音效需求时明确说明不适用，不为凑内容制造问题。
- 发言包括角色音色、台词与情绪；音效触发条件、重复播放约束、资源标识和验收依据。不得声称未生成或未试听的音频已通过验收。
- 圆桌结构化评审由文本模型完成，默认沿用本地 Nemotron；音频生成由音频模型完成。音频生成模型不直接承担圆桌 JSON 评审协议。
- 保留 OpenClaw 按 Agent 选择其他文本模型的能力；迁移已有配置时增加新角色，不重建凭证，不覆盖既有模型路由。

## 音效工作台

- 在现有工作台添加“模组音效”入口，提供 NPC 配音、物品音效、交互音效三种类别。
- NPC 输入：素材名、角色描述、台词、情绪／表达要求。音效输入：素材名、事件描述、声音质感。默认请求独立素材，无背景音乐；时长要求作为创作意图，不承诺模型精确遵循。
- 可以关联圆桌，将音效方案作为可编辑生成描述；点击生成前展示最终提示词。会议发言本身不自动发起音频生成。
- 展示排队、生成、完成或失败状态；完成后本地试听、下载单个音频及素材 ZIP。素材清单记录类别、资源标识、模型和生成描述，不含凭证或请求头。
- 音频存于忽略提交的本地数据目录。音频格式以接口实际返回并验证的格式为准；未验证前不承诺自动转换或完整资源包可直接在游戏加载。

## 模型适配

- 使用统一音频 provider 接口隔离生成、结果格式和错误处理，第一版实现 StepFun。配置只允许已注册适配器，未知适配器明确报错，不静默替换模型。
- 默认模型：`stepaudio-3-gen-preview`。官方模型介绍确认支持对白及音效，端点为 `POST /v1/audio/generate`。
- 实现前须取得官方请求／响应参数文档，验证返回类型、格式、大小和超时行为，不能照搬普通 TTS 或第三方代理接口。
- 网络超时不自动重复生成，避免请求已完成但响应丢失时重复调用；用户可明确重试。错误显示经过脱敏的类别，不回传上游原始响应。

## 密钥与发布

- 后端读取本地 `STEPFUN_API_KEY`，配置对象不打印密钥；浏览器只能获得“已配置／未配置”。
- 将私密配置加载接入现有 `run_studio.py` 的项目专用配置链；支持环境变量覆盖，示例文件只保留空值。
- 不将密钥传入角色提示词、检索索引、会议记录、音频任务数据库、前端存储或 ZIP。
- `.gitignore` 排除私密环境文件及运行数据，并保留无密钥配置样例。
- 发布工具按显式源码目录／文件白名单打包，排除 `.git`、虚拟环境、运行数据、私密配置及日志。另检查待发布文件的实际内容，发现疑似凭证时阻止打包；不能仅依赖 `.gitignore`。

## 验证与交付

1. 测试六人角色配置、每轮调用顺序，以及调音虾尾提出的问题未关闭时不可达成共识。
2. 验证旧会议可读、已有角色配置可迁移、独立 OpenClaw 导出包含新 Skill。
3. 用模拟 HTTP 验证 StepFun 请求、无密钥提示、鉴权错误、超时、非音频响应、大小限制和任务恢复。
4. 用测试密钥哨兵检查公开配置、日志、API 响应与发布包均不泄漏。
5. 浏览器验证 NPC 与音效表单、任务状态、试听和下载；配置真实密钥后各生成一份短示例，单独记录实际接口验证与听感验收。
