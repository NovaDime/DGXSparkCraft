# SparkCraft 部署说明（赛事提交版）

本说明覆盖本地算力部署、模型优化和 Agent Skills 设计。逐步安装与故障处理补充见 [DGX Spark 部署与双击启动](DGX-Spark部署.md)。

## 1. 环境与首次启动

目标设备为 Linux ARM64 的 NVIDIA DGX Spark。准备 Python 3.12+、venv、NVIDIA 驱动、Docker 和 NVIDIA Container Toolkit，确保当前用户能够使用 Docker 访问 GPU。网络需要访问 Node、npm、Python 包索引、Docker 镜像源与 Hugging Face。模型、镜像和缓存需要额外磁盘空间，源码便携包不包含这些大文件。

```bash
# 在解压后的 SparkCraft 项目目录执行
chmod +x *.sh
./一键部署.sh --dry-run
./一键部署.sh
```

脚本首先探测 `http://127.0.0.1:8000/v1/models`。发现匹配的 Nemotron 服务时复用；端口冲突或已有GPU计算进程但没有匹配服务时停止提示，不停止或替换原服务。只有条件满足才创建模型容器。随后准备项目内的 Node、OpenClaw 和 Python 环境，生成专用 Gateway 配置及桌面入口，启动工作台并打开 `/studio`。

已有环境直接使用 `./启动.sh`。可用 `./安装桌面快捷方式.sh` 生成当前目录对应的双击图标；搬迁后重新生成，不携带作者机器的绝对路径。无图形界面的主机需通过浏览器访问本机转发端口，不能期待远端 SSH 会话弹出桌面浏览器。

## 2. 本地算力如何承载 Agent

调用链为：浏览器 → 本地 Python 调度器 → 项目 OpenClaw Gateway（19789）→ vLLM（8000）→ DGX Spark GPU。Studio（8765）、Gateway 和模型服务均以本机访问为默认边界。使用云端文本模型时，对应角色的调用改为用户指定服务，相关资料会发送给该服务；其他角色仍可使用本地模型。

每个角色有独立职责和工作区，由主程序显式提供技能、当前方案、问题和检索片段。应用统一控制推理通道、超时、输出结构和文件落盘。多个 Agent 可以共用一个模型，避免按角色重复加载同一权重。游戏代码在单独的工作目录生成，不覆盖导入源码，不自动执行模型写出的任意命令。

## 3. 大模型优化及验证范围

| 优化 | 当前实现 | 边界 |
|---|---|---|
| 低精度权重 | Nemotron NVFP4 模型 | 属于已发布量化权重的部署，不是本项目训练或量化算法成果 |
| KV cache 与前缀复用 | 本机已配置 FP8 KV cache、prefix caching | 未做关闭/开启对照性能测试，不声明提升比例 |
| 内存和并发控制 | 现运行容器 `gpu-memory-utilization=0.45`、`max-num-seqs=4` | 一键部署新容器预设利用率0.85；两者不是同一运行快照，需结合设备负载调整脚本 |
| 推测解码 | 部署脚本预置 DSpark 配方 | 本机当前容器未启用；首次下载与新容器配方仍需目标机验收 |
| 请求上下文控制 | 按会议/角色/阶段隔离调用，注入当前方案与相关片段 | 不把全部历史一直堆入会话；1M为单次上下文上限，实际仍受模型和应用更小限制约束 |
| 迭代控制 | 有界修复、优先复核旧问题、真实失败保留 | 不无限重试；不通过删除真实分歧制造共识 |

当前模型容器允许 `max-model-len=1048576`，这只是服务配置，不证明任意1M请求都能在当前显存和并发下成功。应用字符预算、单次上下文预算和输出上限共同约束实际请求。不同优化组合需要相同输入下记录耗时、token使用、错误率和资源占用后才能比较；本次不提交未经测量的加速数字。

## 4. Agent Skills 如何设计与加载

| 成员 | Skill 文件 | 主要决策与交接 |
|---|---|---|
| 主管虾 | [roundtable-host](../skills/roundtable-host/SKILL.md) | 整理范围、分歧、收束与人工审核任务单 |
| 策划虾 | [minecraft-design](../skills/minecraft-design/SKILL.md) | 状态表、交互规则、失败反馈与验收场景 |
| 数值虾 | [minecraft-balance](../skills/minecraft-balance/SKILL.md) | 量纲、周期、概率、叠加与边界推演 |
| 程序虾皮 | [modsdk-feasibility](../skills/modsdk-feasibility/SKILL.md) | 端别、接口证据、生命周期和最小模块职责 |
| 调音虾尾 | [minecraft-audio](../skills/minecraft-audio/SKILL.md) | 台词、音效资产ID、播放规则与音频验收 |
| 程序虾米 | [modsdk-review](../skills/modsdk-review/SKILL.md) | 独立反例、修复复核和回归场景 |
| 程序虾仁 | [modsdk-coding](../skills/modsdk-coding/SKILL.md) | 在批准范围内提交文件与API依据 |
| 经验复用 | [repository-learning](../skills/repository-learning/SKILL.md) | 检索来源和人工采纳的经验记录 |

每份技能包含适用范围、角色流程、边界、输出要求，并以参考手册补充专业实例。`SkillCatalog`读取技能；当前实现会拼接该角色目录内全部 Markdown 参考资料，因此手册应保持精炼，并不是由模型自行按需读取所有外部文件。技能与参考文件指纹记录用于追溯输入，模型返回的技能ID不能证明工具实际执行。

统一协议要求角色只关闭自己有修订依据的问题；“设计阻断”进入问题台账，“制作后的验收”进入建议。该分工减少重复争议，同时不能放过未查证且不可替代的核心能力。部署生成的 OpenClaw 角色工具配置采取最小权限，数值脚本等只有实际工具输出时才可声称执行。

## 5. 知识、音频与人工审核

Minecraft 官方API与指南默认加入前置上下文。基础规则、固定版本参考快照和官网正文分别标注；首次联网尝试同步，失败不捏造内容。代码上传为可选项，支持在知识界面补充离线资料。模型识别摘要保留“待人工核对”，不替代原文。

StepAudio 是可选云端音频依赖。在人工审核面板填入自己的 StepFun 密钥，核对台词和调用内容，再批准任务单。密钥只保存至本机 `data/private/`，不把凭证填入技能或 `.env.example`。真实音频生成可能计费，超时不会无限自动重试。生成音频校验、格式转换、资源声明、代码引用及目标游戏试听分开记录。

## 6. 运维、复现与发布

```bash
./后台监控.sh
python3 scripts/linux_studio.py status
./结束.sh
.venv/bin/python scripts/package_release.py --github --version 1.2.0 --output ../SparkCraft-1.2发布包
```

发布脚本拒绝覆盖已有目录；更新发布时先保留旧版本再生成。`data/`、私有配置、历史任务、用户源码、Git历史、模型权重和已安装运行时不随源码包交付。停止脚本不停止模型服务，避免影响其他使用者。

发布包不包含历史测试记录。首次部署请检查本机模型与 OpenClaw 连接；真实音频生成需要配置 StepFun 密钥，模组兼容性需要目标游戏验证。
