# SparkCraft 项目说明文档

项目版本：1.1.0；材料核对日期：2026-09-27。

作品名称：**SparkCraft—助力开发你想要的世界**。

团队：**NVIDIA Developer社区说的都队**。

## 项目定位与作品特点

SparkCraft 是面向游戏 UGC 开发者的本地多智能体协作工作台。项目以 Minecraft 中国版模组开发为主要场景，将开发者的自然语言创意转化为可讨论的方案、可人工审核的任务单，以及可查看源码、检查记录和资源文件的开发产物。系统关注需求、实现、检查与迭代，不承担地图制作、联机运营、测试账号管理、上架或收益业务。当前默认目标为中国版基岩 1.24，但客户端标签不能替代对具体 ModSDK 版本及游戏脚本运行时的核验。

与单次问答式代码生成相比，SparkCraft 将需求中的歧义、实现限制、参数计算和声音设计分别交给不同角色处理。主管虾负责组织议题与收束方案，策划虾负责玩家流程和状态规则，数值虾负责参数、概率与边界推演，程序虾皮负责技术可行性和接口证据，调音虾尾负责 NPC 对白与交互音效，美术虾绘负责贴图、UI 九宫格和序列帧资源规划，程序虾米独立检查逻辑反例。编码执行由程序虾仁承担。七位圆桌成员不是七份独立模型权重，而是拥有不同技能、职责、调用范围和模型路由的 Agent，可复用同一个本地 Nemotron 服务，也可按角色配置云端文本模型。

界面使用像素风虾办公室展示角色，并为不同岗位设置不同动作。开发者可以点击角色查看职责及模型，在会议记录中回看问题、修订与结论。开发任务和会议记录支持可恢复删除，会议记录支持折叠；开幕动画与工作台入口统一品牌。视觉呈现服务于理解协作流程，不代替实际执行证据。

## 核心亮点

第一，系统将“形成共识”与“批准执行”分开。会议只有满足调度器的评审条件后才能形成共识，仍未解决的问题不会因为达到轮数而被自动忽略。共识之后先整理程序与音效任务单，用户核对目标版本、制作范围、台词和资源标识并批准，后端才发起制作。任务单版本、批准记录和执行结果关联保存，避免方案修改后继续沿用旧批准。

第二，本地算力承担反复讨论、代码生成、独立审查和文档识别。DGX Spark 上的 Nemotron 通过 vLLM 提供本机接口，OpenClaw 为角色提供独立工作区和调用入口。主程序管理排队、上下文及停止条件，真实推理失败会保留错误，不回退为看似成功的模拟内容。显式模拟模式只用于检查工作流，不作为 AI 效果展示。

第三，官方资料和项目经验具有来源。Minecraft 知识空间默认提供官方 API 与开发指南入口、开发核验基线及可读取的参考片段，这些内容不依赖用户主动选择代码库才注入 Agent 上下文。用户可选导入本机源码目录、ZIP 或补充文档；检索结果保留文件与行号，模型识别摘要与原文分开。经验必须经人工采纳后参与后续检索。这里的持续学习是索引与经验复用，没有训练或修改模型权重。

第四，声音进入方案与代码的同一交付流程。调音虾尾在讨论阶段定义台词、声音材质、资源标识和触发规则，批准后由 StepFun 音频适配器调用 `stepaudio-3-gen-preview`。程序使用相同的资源标识接入声音事件，后端校验音频并转换为游戏资源格式，再检查声明和引用的一致性。接口适配与自动化测试已经实现，但尚未完成真实 StepFun 音频生成和目标游戏整体验收，不能把模拟响应称为真实作品音效。

## 技术实现与架构设计

浏览器工作台使用 HTML、CSS 和原生 JavaScript，通过本地 FastAPI 服务访问会议、开发、知识和交付接口。Python 宿主管理可信文件操作、静态检查及 ZIP 打包，SQLite 保存可恢复的任务快照。模型负责提出方案、代码文本和审查建议，不直接取得任意终端执行权，上传的源码也不会被作为程序自动执行。

会议引擎按角色和阶段组织调用，每轮围绕当前方案评审。问题台账保留提出者，后续优先复核该角色自己的未解决问题；主持整合意见但不能代替专业角色凭空关闭问题。单场讨论上限可配置为 3 至 1000 轮，同时受累计 1M token 预算保护。累计预算不等于每次请求都填入 1M 上下文，实际请求还受字符限制、输出限制及运行中推理服务容量约束。

编码流程在独立工作区中检索参考源码，生成受约束的文本文件，执行静态检查，交由独立角色审查，并进行有次数上限的修复。集成阶段核对入口、行为包与资源包清单、音频资源及引用，缺失必要素材或审查未通过时保留阻断原因。最终状态为“已打包·待游戏验收”，而不是未经运行就宣称模组完全可用。

## 已实施与计划中的优化

已经实施的优化包括：本地模型复用、按阶段隔离模型会话、限制上下文和输出长度、单推理通道控制、旧问题优先复核、将后续验收与设计阻断区分、已有声音产物复用，以及以带来源片段替代整库无差别注入。Skills 将角色工作流、规则边界和实例分开组织，避免单纯增加提示词长度。模型服务当前使用 NVFP4 权重、FP8 KV cache 和前缀缓存；部署脚本还提供 DSpark 推测解码配方，但当前运行容器未启用 DSpark，不能声称测得其加速收益。

后续工作包括完整官方文档获取、更多文件识别能力、其他游戏开发适配及更系统的游戏内验收。其他游戏入口目前明确显示“未来更新”。尚未建立统一性能基准，不填写未经测量的吞吐提升、成本下降或成功率数字。

## 提交与复现

完整使用步骤见[部署说明](部署说明.md)，组件和模型版本见[技术栈说明](技术栈说明.md)，实际架构入口见[架构说明](architecture.md)。Skills Markdown 与参考手册随源码交付。发布包排除凭证、用户代码、历史会议、运行环境和模型权重，首次部署需要联网下载依赖。开源仓库发布、B站演示视频和团队合影由团队按赛事表单提交；本文不代表已经完成外部提交。


当前美术制作按多模态模型方向预留 API 配置入口，密钥本机保存；尚未启用图片生成适配器，不能将文字策划冒充生成图片。有新美术素材缺口时阻止打包，或经人提出修改后重新讨论、改用已有资源。完整策划和初始想法统一从工作台提交，方案修改保留父会议关联，需再次人工批准；代码库从知识页面导入，由后续任务自动检索引用，原始工程不会自动混入新产物。
