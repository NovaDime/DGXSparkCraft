# Agent Skills 黑客松对齐说明

作品定位：面向 Minecraft 中国版模组开发者的专业协作工作台，在 DGX Spark 本地模型支持下，从需求与圆桌评审进入实际代码交付，再用可审核的仓库知识帮助下一次开发。

## 赛题来源和证据边界

用户提供 [本届赛题知乎链接](https://zhuanlan.zhihu.com/p/2080680352629134514)。2026-09-25 本次读取失败，未把搜索摘要或猜测当成公告正文。仓库 `web/` 已保存 NVIDIA 企业开发者社区 2026-08-31 公告《为 Agent 装上专业技能｜第三届 NVIDIA DGX Spark 黑客松·Agent Skills 开发挑战赛开放报名》，存档标注原地址为 [主办方公众号文章](https://mp.weixin.qq.com/s/dbE5oRai-ikK2LnGoZ-hnw)。以下对齐基于该存档，不声称实时赛制复核。

存档强调完整、可运行的 Agent 应用，通过 Skills 封装专业知识、工具和标准流程，完成从需求理解到任务交付的闭环；作品方向不限，支持开发者工具等方向，并强调 DGX Spark 本地 AI 环境实践。未见其强制使用 StepFun 模型、限定某套 Agent 框架或公布评分权重，因此不将这些猜测写成参赛要求。

存档中的预赛开发与提交窗口为 2026-09-20 至 09-29，后续评选为 09-30 至 10-08、决赛路演为 10-15。提交方式、材料与时间变化应以主办方当前通知为准；本项目没有代提交赛事材料。

## 从原博客圆桌到开发闭环

[原技术博客](https://developer.nvidia.cn/blog/spark-ugc-ai-roundtable/) 的角色分工、持续讨论和本地推理构成起点。本版保留圆桌，同时把可展示成果从讨论记录扩展为可下载代码、具体差异、验证证据和可审核经验。旧博客中的成本、性能或业务成绩不能算作本次系统的实测结果。

| 赛题强调的能力 | 工作台对应的可演示结果 |
|---|---|
| 完整 Agent 应用 | 可创建任务、查看状态、保留失败、取消或导出产物的开发流程 |
| 专业 Skills | ModSDK 证据与端别规则、实际编码、可信静态工具、有界修复、来源明确的仓库学习 |
| 执行与交付 | 文件级变更、独立工作区、VS Code 打开、ZIP 下载；由宿主写文件并调用可信校验器 |
| DGX Spark 本地算力 | 明确本地模型路由与真实调用记录；报告实际测量，不以模型清单连通等同推理成功 |
| 复用专业知识 | 导入本地代码、追溯片段、采纳经验后在后续任务检索；不把索引宣传为模型微调 |

执行能力在这里指受控的文件交付与静态工具调用。当前流水线不执行上传或模型生成的任意程序，因此不能声称已具备无人值守游戏测试、自动上线或无限自我改进能力。

## 建议的短演示

1. 展示一个已授权导入的真实代码库，检索入口与同类实现，点击带路径和行号的证据。
2. 提交单一、可在几分钟内评审的开发任务。可先展示圆桌已收敛的设计，再转为编码任务。
3. 展示编码、静态工具、独立审查和一次有实际问题触发的修复。若没有错误就如实展示直接通过，不人为伪造检查失败。
4. 在 VS Code 查看实际差异和输出文件，指出哪些是纯逻辑代码、哪些仍需目标 SDK 适配。
5. 保存候选经验，补充真实验证依据后采纳，再提交一个相关但不同的新任务，展示它引用该经验的出处。保留撤销或修订错误经验的路径。

没有目标游戏环境时，用开发产物、可信静态检查和审查日志演示开发环节即可。展示中必须明确“静态检查通过”与“游戏运行验证”是不同结果，不能将模拟模式包装成真实推理。

## 评价与材料

保留固定任务与仓库快照、模型路由、Skill 指纹、生成/修复预算、模型调用数、耗时、真实可用的 token 计数、工具错误、审查结论与人工改动。基线和启用检索的任务条件应相同，用留出的新任务评价复用效果。没有测量数据就不填写提升百分比或声称显著降低成本。

可信校验器有可执行行为测试；模型技能另有前向评估题。将两者分开报告，不能把静态工具测试全部通过称为 Agent 已掌握所有开发任务。

本版有意聚焦开发流程，避免将联机、地图、测试账号、上架与收益纳入演示范围。这个边界来自用户本次目标，不是主办方禁止其他方向。
