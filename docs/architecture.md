# AI 圆桌实现说明

本项目以两篇网页存档中的同一套圆桌机制为依据，从空项目重新编写 Python 主程序和角色 Skills。产出是模组设计方案和评审记录。原博客中的性能、成本、销量和使用效果不作为本次实现的结果。

## 原机制与本版调整

| 博客机制 | 本版实现 |
|---|---|
| 主管发起讨论，专业角色轮流质疑，主管组织下一轮 | 保持；每轮固定顺序评审后再修订 |
| 角色各有专业职责和上下文 | 五个独立 Agent ID 与对应 Skill；每次只传本轮需要的材料 |
| 三名程序员与一名美术角色 | 保留可行性和逻辑审查两名程序员，后者可关闭；去掉补充程序员和美术 |
| 独立助手收集社区动态 | 当前版本未实现，不进入圆桌 |
| 本地模型长期运行 | 预留 OpenClaw Gateway 接口；默认本地规则模拟，Spark 尚待接入 |

顺序为主管开场 → 策划 → 数值 → 程序虾皮 → 程序虾米（可选）→ 主管汇总 → 下一轮。主管开场的首稿是待评审材料，专业角色可以质疑并提出修订。所有专家在一轮中评审同一版方案，同时看到此前角色的本轮意见；主管在轮末形成新版本。

## Python 与推理端分工

Python 3.11 主程序管理会议、队列、轮次、分歧台账、SQLite 持久化、网页展示与导出。OpenClaw 模式使用真实 Gateway 执行指定 Agent；模型配置和角色工具权限位于该 Gateway。五个角色可以共用一个模型后端，Python 全局只推进一场会议、每次只发起一个角色调用。

每次调用使用“会议 ID、角色、轮次、阶段”产生唯一会话范围；不会把不同轮次全部累积进 Gateway 的长历史。当前方案、主管摘要、未关闭问题和本轮意见由 Python 显式传递。字符预算超过上限时停止并说明原因，不静默裁掉仍未解决的问题。

每个角色加载自己的 `SKILL.md`，网页可检查实际提供的 Skill 内容。发言保存所提供文件的 SHA-256；模型返回的 `skill_ids` 只是引用声明。Gateway 中的执行记录才是工具调用证据，文件指纹不能代替工具执行证明。部署包包括完整角色工作区和相应参考文件，安装后需确认它们在真实 Agent 环境中可读取。

## 分歧、共识与故障

专业角色返回 `approve` 或 `revise`，新问题包含标题、具体影响和严重级别。引擎分配问题编号；只有提出者可复核关闭自己的未解决问题，主持者不能代关。关闭理由来自本轮说明，证据充分性仍需真实模型和人工验收，格式验证不能判断论证真伪。

只有参会专业角色全部认可同一版方案、全部登记问题关闭、主管同意且未修改该版方案时，会议才能完成。主管修改了方案，即使其他角色刚刚通过，也必须进入下一轮重审。

默认最多 6 轮，可配置为 1 至 20 轮。达到上限标记待复核；取消、超时、网关错误和服务中断分别保留完成的发言及未解决问题。服务重启将未完成会议标为中断，需要新建议题重新评审，不声称自动续跑或已经形成共识。真实 Gateway 失败不会切换为模拟结果。

## 数据与本地接口

| 接口 | 用途 |
|---|---|
| `GET /api/meta` | 角色、技能说明、示例和当前模式 |
| `GET /api/skills/{skill_id}` | 检查本地提供的 Skill 内容与指纹 |
| `POST /api/meetings` | 传入 `topic`、`constraints`、`max_rounds`、`include_reviewer` 创建会议 |
| `GET /api/meetings`、`GET /api/meetings/{id}` | 历史会议与详细记录 |
| `POST /api/meetings/{id}/cancel` | 停止当前或排队会议 |
| `GET /api/meetings/{id}/export?format=markdown` | 导出方案及会议记录；也支持 `json` |
| `POST /api/provider/check` | 检查当前模式或 Gateway 模型列表连通性 |

本地服务默认仅监听 `127.0.0.1:8765`，单进程单 worker。会议记录写入配置的数据目录；原始网页存档不参与程序执行。Python 主程序不执行模型返回的任意代码，也不负责安装或替换目标游戏的模组。

基础知识与配置依据：[OpenClaw Skills](https://docs.openclaw.ai/tools/skills)、[Gateway OpenResponses 接口](https://docs.openclaw.ai/gateway/openresponses-http-api)。游戏脚本运行时必须以目标 ModSDK 为准，不能与主程序 Python 3.11 混同。
