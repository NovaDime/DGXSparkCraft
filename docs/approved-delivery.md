# 人工审核与自动制作

入口：新版 `/studio#roundtable`，选择已经达成共识的会议，点击「人工审核与制作」。

1. 主管整理程序任务，调音虾尾提取 NPC 配音、物品及交互音效清单。此时只整理任务，不生成代码或音频。
2. 人工核对原方案、目标版本、程序任务、每条声音的资源 ID、台词、音色和触发时机。默认目标为用户指定的「Minecraft 中国版基岩 1.24」，不将这个标签直接当作引擎 `min_engine_version`。
3. 勾选审核声明，点击「审核通过并自动执行」。保存方案指纹、任务单指纹、时间、版本和审核备注。重复批准被拒绝；修改任务单撤销旧批准。
4. 调音虾尾调用 StepFun，生成独立 PCM WAV，检查完整性后转换为单声道 OGG/Vorbis。程序虾仁接收同一份声音事件 ID 和完整触发条件，自动编码、静态检查及最多两次修复；程序模型沿用程序虾皮的模型配置快照，独立审查沿用程序虾米。
5. 汇总行为包、资源包、清单 UUID、互相依赖与声音注册表，再进行集成检查及独立模型审查。缺少入口、音效引用、素材或审查未通过时不提供完成包。

## 音频配置

审核面板展开「StepFun 音频连接」，选择中国区或国际区官方端点，填写密钥。默认模型 `stepaudio-3-gen-preview`。

密钥保存在 `data/private/stepaudio.json`，目录权限 700、文件权限 600；公开 API 只返回配置状态。也可使用服务进程环境变量 `STEPFUN_API_KEY`（优先于文件）。密钥不进入任务提示词、会议记录或模组包。不要把真实密钥填写到 `.env.example`。

生成使用官方 `POST /v1/audio/generate`、`task=text_to_audio`、`roles`、`scripts`、`instruction`，以 `stream_format=audio` 获取音频。超时不自动重试；手动重试会提示可能重复计费。已成功落盘的声音在同版本重试中复用。

## 交付内容

- `addon.zip`：仅包含英文根目录下的行为包和资源包，可解压后作为附加包工程导入中国版开发工作台。
- 完整交付包：包含 `addon.zip`、`CHECKS.json` 和导入说明。报告记录检查、审批指纹和文件哈希，不复制服务器工作区或秘密配置。
- 程序产物可单独下载；音效可在审核面板试听。

静态检查与模型审查不能证明任意生成模组在游戏内可用。完成状态明确标记「已打包 · 待游戏验收」。当前没有自动生成贴图和模型的执行器；若需求必须新增这些素材，任务单将保留阻断项。不会用空白贴图、静音文件或假资源代替。

服务中断后保留状态与已有产物，不自动重新发起可能收费的请求。用户可继续执行或退回修改后重新审核。此应用是本机单用户工作台；审核记录中的 local_user 代表本机使用者，并非多用户身份认证或电子签名。

## 本轮流程更新

工作台的想法和完整策划均先进入策划圆桌。提出修改会创建带 parent_meeting_id、parent_proposal、revision_notes 的新会议，保留原会议和交付；新方案不会复用人工批准。策划角色整理数值结论与制作任务，音效、美术角色补充各自素材清单，再显示人工审核表单。批准后进入制作记录，完成时弹窗并提供下载链接。

美术多模态 API 是测试版配置入口。尚无生成适配器，非空 art_assets 不允许批准执行；复用原版资产的方案仍可开发。不会通过漏掉美术资产清单来伪造完整包。代码库无需工作台选择，全库相关片段用于圆桌及编码参考；检索并非模型权重训练。
